# 路线图：从「能跑」到「真的有人用」

> 原始设想来自作者手写的《远大目标》，这里把它拆成可执行的三步，并标注哪些该先做、哪些不该现在做。

## 一句话原则

**先做「能被人用」，再做「更多人用」，最后才做「多端」。**

技术难度从低到高排，而不是按想做的欲望排。

---

## M0：能跑（已完成）

- [x] 请求体校验、API Key 鉴权
- [x] 25+ 接口测试，不联网不花钱
- [x] 超时、重试、失败可见（502）

现在的状态：**一个能对外提供服务的后端 + 一个只有自己会用的前端。**

---

## M1：小范围可用（目标 1 个月内）

> 完成标准：**≥10 个同学真的在用，能收到 ≥20 条真实提问记录。**

为什么先做这个：真实用户才会暴露你没想到的问题。这次 PR 里的三个 bug
（`/docs` 白屏、Gradio 第二轮 422、48 秒静默成功）**全都是"真的去用"才发现的**，单测一个都没抓到。

### 要做什么

| # | 任务 | 难度 | 说明 |
|---|---|---|---|
| 1 | **多 provider 切换** | 低 | 默认 SiliconFlow / 自定义 URL+模型名 / 本地 Ollama 三选一 |
| 2 | **对话持久化**（SQLite） | 低 | 刷新页面不丢历史；也是多会话的前提 |
| 3 | **多会话管理** | 低 | 新建 / 切换 / 删除 |
| 4 | **一个别人能访问的地址** | 中 | 内网穿透、校园网、或一台最小云服务器 |
| 5 | **邀请码白名单** | 低 | 复用现有 `GATEWAY_API_KEY`，一人一码 |

### 技术难点

- **provider 抽象**：把 `ChatOpenAI(...)` 的构造参数化。这个改造的价值远超功能本身——
  它逼你想清楚"哪些是模型无关的、哪些是 provider 特有的"。面试聊架构时这就是素材。
- **本地 Ollama**：需要显卡。没有 GPU 的话 7B 模型跑不动，可以先只做"自定义 URL"这一档。

### 不要做的事

- 不要一开始就搞注册登录系统。邀请码够用，而且更安全。
- 不要在 M1 阶段做 UI 美化。**能用的丑界面 > 好看的空壳。**

---

## M2：公开服务（目标 3–6 个月）

> 这一阶段的门槛**不在技术**，在运营和合规。

### 要做什么

| # | 任务 | 难度 | 说明 |
|---|---|---|---|
| 1 | SSE + 断流错误帧 | 中 | 修掉"第 2 个 chunk 之后断流静默结束" |
| 2 | **Skills 库**（可插拔工具） | 中 | 和 MCP 同一套思路：定义 schema → 注册 → 模型决定调用 |
| 3 | 多供应商降级 | 中 | 主模型挂了自动切备用（小模型 / 本地） |
| 4 | 限流 + 配额 + 用量计量 | 中 | 否则 token 账单会被陌生人刷爆 |
| 5 | 内容安全过滤 | 中 | 输入/输出双向 |
| 6 | 生成式 AI 服务备案 | **高（非技术）** | 国内公开提供生成服务的前提条件 |

### 真正的门槛

1. **钱**：公开 = 有人会刷。没有限流和配额，一晚上就能烧掉一个月生活费。
2. **合规**：面向公众提供生成式 AI 服务需要备案，这是法律要求，不是技术选型。
3. **运维**：挂了要有人管，日志要能查，这些比写功能累。

> 所以 M2 的正确姿势是：**先小范围（M1），确认真的有人愿意用，再考虑公开。**

---

## M3：多端（6 个月后，按需）

| 端 | 方案 | 难度 | 备注 |
|---|---|---|---|
| 桌面 exe | PyInstaller 或 Tauri 包一层 | 低 | 本质是包装，技术含量不高但演示效果好 |
| 安卓 App | Tauri Mobile / Capacitor 套壳 | 中 | 复用现有 Web 前端，不用重写 |
| iOS | 同安卓套壳，但需要 | **高（非技术）** | Apple 开发者账号 $99/年 + 必须有 Mac |

**建议：M3 永远排在 M1/M2 之后。** 多端是"放大器"——后端不行的时候，多一个端只是多一个崩溃的地方。

---

## 明确不做的

| 项目 | 为什么不做 |
|---|---|
| iOS | 成本（$99/年 + Mac）与收益不成比例，而且套壳 App 过审很难 |
| 真·公开（无备案、无限流） | 法律风险 + 账单风险，且不能体现工程能力 |
| 独立 agent 流（多 agent 编排） | 容易做成玩具。**先有 skills 库和真实用户，再谈编排** |

---

## 排序原则

```
M1 有人用   →  M2 更多人用，且扛得住  →  M3 多端
   技术为主        运营 + 技术             包装
```

每完成一个里程碑，回来更新这张表：把 `[ ]` 改成 `[x]`，把新的认知补进来。
