## 每个 PR 留下的一个判断

比数字更值得记住的，是这些判断后来被反复引用。

| PR | 留下的判断 |
|---|---|
| #1 | **分支选错，成果就落在 master 之外。** 第一次合并时 head 指错了分支，测试和文档没进 master，只能事后用 `chore:` 补一次。 |
| #2 | **失败必须让客户端看见。** 改之前上游挂了会返回 `200 + 半句话`，监控看不到、日志没有——"静默成功"比"报错"危险得多。 |
| #3 | **别让客户端传 URL（SSRF）；模型的自我描述不可信。** 实测中三个模型分别自称通义千问、OpenAI、AI 助手——只有 `X-Model` 响应头说了实话。 |
| #4 | **延迟 ≠ 质量。** 降级链一开始按实测延迟排，结果本地 0.5B（93ms）排到了 DeepSeek（481ms）前面——最快的是最弱的。改成按配置顺序排，延迟只用于显示。另外：**探测失败不该踢掉后端**，只标"未验证"，否则一次网络抖动就能误杀一个能用的备用。 |
| #4 | **降级是"用更慢的失败换可能成功"，而且是静默花钱的。** 主 key 错且有备用：0.7s 502 → 1.6s 200（赚）；备用也全挂：0.7s 502 → 最差 50s 才 502（亏）。链的顺序就是花钱顺序，必须写进文档。 |

## 怎么加一行

合并完 PR，把这一行填上：

```
| 4 | YYYY-MM-DD | 题目 | N | N | +N / −N | N |
```

数字从哪来：

```powershell
# 提交数、文件数、改动量（相对第一父，即这个 PR 带来的实际改动）
git diff --shortstat <merge>^1 <merge>
git rev-list --count <merge>^1..<merge>

# 测试数
python -m pytest -q
```
