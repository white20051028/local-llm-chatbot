## 一句话

**一个能回答「我大二能不能转专业」的问答系统，并且能证明它答得准。**

---

## 为什么是这个选题

| 硬标准 | 校内教务的答案 |
|---|---|
| 有真实用户 | 同班同学、学院群，一周能凑 30 个真问题 |
| 有标准答案 | 教务处政策文件是唯一答案，天然适合做评测集 |
| 数据一周能拿到 | 官网 PDF、学院通知，都是公开的 |

**关键优势：我自己就是学生，这是复制不了的信息优势。**

---

## 四条必须手搓（不能用 LangChain 高层封装）

| 模块 | 手搓到什么程度 | 为什么 |
|---|---|---|
| 切分 | 按标题层级 + 滑窗 + 重叠，做 3 组参数对比 | 「chunk_size 为什么是这个数」只能答自己的对比表 |
| 检索 | BM25 + 向量召回 + RRF 融合 + bge-reranker | 会写 RRF 的人不到 20% |
| 生成 | prompt 组装、引用编号注入、**拒答策略** | 防幻觉是 To-B 硬需求 |
| 评测 | 100–120 条标注集 + Ragas + 优化前后对比 | **这是与所有同类项目的分水岭** |

## ★ 与 P1 的联动：复用网关

P2 的生成阶段**不重新写一套模型调用**，直接调 P1 的网关：

```
用户提问
   ↓
P2 检索（BM25 + 向量 + RRF + rerank）
   ↓
组装 prompt（引用编号注入）
   ↓
调 P1 网关  ← 重试、超时、502、计量、多 provider 全部白拿
   ↓
流式返回（带引用编号）
```

**为什么这件事值得单独记下来：**

1. 它让 P1 的价值被**实际使用**验证，而不只是"我设计了一个网关"
2. 面试时可以说：「我的 RAG 项目没有重写模型调用层，直接复用了第一个项目的网关——
   因为那个网关本来就是为『所有 AI 应用提供统一接入』设计的。」
3. 它逼我保证 P1 的接口真的通用（而不是只为 Gradio 写死的）

**要验证的**：P2 里换 provider（云端 / 本地）时，RAG 的检索层完全不用改。

## 面试会被追问的（提前准备答案）

| 问题 | 要点 |
|---|---|
| chunk_size 怎么定的 | 三组对比数字 + 「大块保上下文、小块保精度」 |
| 混合检索分数怎么融合 | RRF：按排名而非分数，避免 BM25 与余弦不可比；k=60 的作用 |
| rerank 提升的代价 | +400ms、+50% 成本；判断是 To-B 场景准确率 > 首字延迟 |
| 怎么防编造 | 三层：prompt 约束引用编号 → 生成后校验引用存在 → 检索分低于阈值直接拒答 |
| 评测集自己标的算数吗 | 主动承认偏差 + 用「陌生问题组」交叉验证 |
| 检索不到时什么表现 | 返回「没找到，你可能想问 A/B/C」+ 兜底转人工，并记录 query |
