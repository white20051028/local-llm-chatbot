## 二、第一阶段：把三个功能补上

### 2.1 请求体校验（Pydantic）

**改了什么**

把 `chat()` 上那 7 个 `Body(...)` 参数，换成一个 `ChatRequest` 模型：

```python
# 改造前
async def chat(
    query: str = Body(...),
    history: List[dict] = Body([]),      # ← 任何字典都能塞进来
    temperature: float = Body(0.7),      # ← 没有任何上下界
    ...
):

# 改造后
@app.post("/chat", dependencies=[Depends(require_api_key)])
async def chat(payload: ChatRequest):    # ← 进函数前就已校验完毕
```

**三个关键决定**

1. **为什么是 422 而不是 500**
   校验由框架在进入函数前完成，非法请求属于"客户端错误"（4xx）。
   如果等调用大模型时才炸，那是"服务端错误"（5xx），会误导排查方向。

2. **`role` 用 `Literal` 而不是 `str`**
   `history` 原来是 `List[dict]`，`role` 写成 `"root"`、缺 `content` 字段，全都放行。
   用 `Literal["system","user","assistant"]` 之后，非法值在类型层面就被拒绝。

3. **`extra="forbid"`**
   多传了不认识的字段就报错。这一条最容易被忽略，但最救命：
   前端把 `temperature` 拼成 `temprature` 时，不 forbid 就会**静默丢弃**该字段，
   模型仍然用默认值 0.7 跑 —— 你以为调了，其实没调，且任何地方都不报错。

### 2.2 鉴权（X-API-Key）

**改了什么**

新增 `auth.py`，一个依赖函数，挂在路由的 `dependencies=[...]` 上。

**三条原则**

1. **fail closed**：服务端没配 `GATEWAY_API_KEY` 时，拒绝所有请求（500），
   而不是默认放行。否则哪天忘了加环境变量，服务会静默变成完全公开的。
2. **常数时间比较**：用 `secrets.compare_digest` 而不是 `==`。
   `==` 比到第一个不同的字符就返回，攻击者能靠测响应时间逐字符猜出密钥
   （timing side-channel，时序侧信道）。
3. **不区分"没带"和"带错"**：一律 401，不给攻击者额外信息。

顺带加了 `/health`（免鉴权），留给部署探活用。

### 2.3 测试

**改了什么**

新增 `test_chat.py`，用 pytest + `TestClient`。

**关键技巧：按接口造假**

模型的全部用途就是 `bind(...)` 和 `astream(...)`，所以假模型只要有这两个方法就够：

```python
class FakeModel:
    def bind(self, **kwargs): return self
    async def astream(self, messages):
        for piece in ("你", "好"):
            yield SimpleNamespace(content=piece)
```

再用 `app.dependency_overrides[get_model] = lambda: fake_model` 把它换进去。

好处：**不联网、不花钱、1.8 秒跑完 14 个测试**，改完代码随手就能跑。

## 三、第二阶段：真跑起来才暴露的 bug

这一阶段最值钱。**所有单测都是绿的，但一上真环境就出问题。**

### 3.1 配置缺失时，422 变成了 500

- **怎么发现的**：18 个单测全绿，但起了真服务再打一遍，三个本该 422 的请求全变 500。
- **根因**：`.env` 没填 `SILICONFLOW_*` 时，`ChatOpenAI(None)` 抛的是 pydantic 的
  `ValidationError`，而不是 `HTTPException`，FastAPI 兜底成 500。
  更麻烦的是：**FastAPI 先解依赖、再校验请求体**，这个 500 会盖住本该出现的 422。
- **修法**：显式检查三个必需变量，缺了就抛一句人话的 500。
- **教训**：单测里用 `dependency_overrides` 换掉了模型，就等于**从来没碰过真实配置**。

### 3.2 照着 `/docs` 点一下就 422

- **现象**：打开 Swagger，点 Try it out，填好 key，Execute → 422。
- **根因**：Swagger UI 生成示例时对枚举**取第一个值**，而 `Role` 是
  `["system","user","assistant"]`，于是它把 `history` 填成 `role="system"`，
  正好撞上"history 禁止 system"那条防注入规则。
  **文档示例自身不合法。**
- **修法**：给模型一个显式的 `json_schema_extra={"example": ...}`，并加一条测试
  断言"示例能被 `model_validate` 通过、且真发一次请求返回 200"。
- **教训**：自己写的校验，第一个卡住的往往就是自己的文档。

### 3.3 网页聊天第一轮正常，第二轮必挂

- **现象**：
  ```
  [{'field': 'history.0.content', 'reason': 'Input should be a valid string'},
   {'field': 'history.1.content', ...} ...共 8 条]
  ```
- **怎么查的**：把 `content` 的几种可能形状逐个打一遍，复现出逐字相同的报错；
  再翻 Gradio 源码，确认 `ChatMessage.content` 的类型是"字符串**或**内容块数组"。
- **根因**：Gradio 6 用「内容块数组」表示一条消息（为了支持多模态），
  即 `[{"type":"text","text":"..."}]`。第一轮能过是因为 `history` 是空的。
- **修法**：不在前端拆数组，而是让**后端两种都接受** ——
  OpenAI 的 chat API 本来就这么设计，作为兼容网关应该跟着协议走。
  用 `mode="before"` 的校验器把各种形态统一抽成字符串。
- **教训**：单测全绿，是因为一直用**自己想象的格式**在测。

### 3.4 环境：`ssh git@github.com` 报 `Unknown error`

- **根因**：本机 hosts 被加速工具写入了上百条 `127.0.0.1 <域名>`，包括 `github.com`。
  它只在本地开了 443 做网页反代，没开 22，所以 SSH 连到 `127.0.0.1:22` 被拒。
- **修法**：在 `~/.ssh/config` 里让 `github.com` 走 `ssh.github.com:443`。
- **教训**：`Unknown error` 不是网络差，先 `Resolve-DnsName` 看域名解析到哪儿。

### 3.5 安全：token 明文写在 remote URL 里

- **现象**：`.git/config` 里是 `https://ghp_xxxx@github.com/user/repo.git`。
- **影响**：`git log -p --all` 查过，token **没有进入提交历史**，所以没被推到公开仓库；
  但它明文躺在本地，只要目录被同步、压缩、分享就会泄露。
- **修法**：撤销 token → 重新生成（设 90 天过期）→ 改用 SSH。
- **教训**："没被提交"不等于"没泄露"。凭证不该出现在任何会被复制的文件里。

### 3.6 改了代码不生效

- **现象**：改完 `schemas.py` 加了 `extra="forbid"`，`smoke.py` 打过去还是 200。
- **根因**：Python 在 `import` 时把模块读进内存并缓存，之后改磁盘上的 `.py`，
  内存里那份不会变。uvicorn 启动后不会自动重载。
- **修法**：开发时用 `uvicorn fastapi_bot:app --reload --port 6066`。
- **重要例外**：`--reload` **只监听 `.py`，不监听 `.env`**。改配置必须手动重启。

### 3.7 打开 `/docs` 一片白

- **现象**：`http://127.0.0.1:6066/docs` 返回 200，但浏览器一片空白，什么都不显示。
- **怎么查的**：
  1. 先确认后端没死：`/docs` 200、`/openapi.json` 200、`/health` 200 —— 说明服务正常；
  2. 把 `/docs` 返回的 HTML 打出来，看它引用了哪些外部资源 →
     `https://cdn.jsdelivr.net/npm/swagger-ui-dist@5/swagger-ui-bundle.js`；
  3. 而代码里写的是 `cdn.bootcdn.net` —— **对不上**。
- **根因**：两层叠在一起。
  1. **FastAPI 0.143 已经删掉了 `swagger_js_url` / `swagger_css_url` 这两个参数**。
     而 `FastAPI.__init__` 带 `**extra`，所以传进去**既不报错、也不生效**，
     被静默吞掉了；
  2. 于是实际生效的是默认 CDN `cdn.jsdelivr.net`。那个域名在国内基本连不上，
     Swagger 的 JS 永远加载不到 —— HTML 是 200，页面却纯白。
- **修法**：把资源本地化，彻底不依赖任何 CDN。
  1. 下载 `swagger-ui-bundle.js` + `swagger-ui.css` 到 `static/`；
  2. `FastAPI(docs_url=None, redoc_url=None)` 关掉自带路由；
  3. `app.mount("/static", StaticFiles(directory=<绝对路径>))`
     （用 `__file__` 算绝对路径，否则换个目录启动就找不到）；
  4. 自己写 `/docs` 路由，调用 `get_swagger_ui_html(swagger_js_url="/static/...")`
     —— 被删的只是 `FastAPI.__init__` 上的参数，这个函数本身仍然支持自定义；
  5. 顺手加一条 `/` → 307 跳 `/docs`，免得访问根路径看到 `{"detail":"Not Found"}`。
- **验证**：`/docs` 的 HTML 里外部资源为空；`/static/*.js` 返回 200 且
  `Content-Type: application/javascript`；`/` 返回 307、`Location: /docs`。
- **教训**：**框架升级会静默吞掉旧参数**。
  "参数不报错"不等于"参数生效"——遇到"配置改了没反应"，
  第一步永远是验证它到底有没有被用上，而不是继续改业务代码。

## 四、第三阶段：补齐本轮遗漏的防御

跑通之后回头做 code review，发现自己写的东西缺了一层——**缺的正好是自己踩过的坑**。

| 补的东西 | 如果不补会怎样 | 对应踩过的坑 |
|---|---|---|
| `json_schema_extra={"example": ...}` | `/docs` 一按就 422 | 3.2 |
| `content` 归一化（`_extract_text`） | Gradio 第二轮全挂 | 3.3 |
| `field_validator` 禁 `history` 里的 `system` | 调用方伪造 system 指令，覆盖 `sys_prompt` | 还没踩，但它是 prompt 注入 |
| `RequestValidationError` 异常处理器 | 422 是一坨三层嵌套 JSON，字段名要自己挖 | — |
| 懒加载 `get_model()` + 缺配置护栏 | `.env` 少配一个变量，服务根本起不来 | 3.1 |
| `media_type="text/plain; charset=utf-8"` | 中文在某些客户端会乱码 | — |
| 删掉调试 `print`、清理死 import | 死代码、重复导入，code review 一定被提 | — |
| `.gitignore` 补 `.pytest_cache/` | 每次跑测试都在仓库里留垃圾 | — |
| swagger 资源本地化 + 自定义 `/docs` | `/docs` 一片白（jsdelivr 国内不通 + 旧参数已被移除） | 3.7 |

**一句话**：这些不是"加分项"，是**把踩过的坑固化成代码里的防线**。

## 五、三轮下来最值钱的四条规律

### 1. 单测绿 ≠ 能用

三次翻车（3.1 / 3.2 / 3.3），都是"测试全过、实际用不了"。
因为测试是我写的，它验证的是**我以为的用法**。

> 每个接口的最后一条测试，要用**真实调用方的真实格式**写一遍。

### 2. 出问题的地方几乎都在"边界"

- 以为配置总是齐全的 → 3.1
- 以为调用方会照文档传 → 3.2
- 以为 `content` 是字符串 → 3.3

这三条本质是同一件事：**我在用自己的假设验证自己的假设**。

### 3. "改了没生效"永远先怀疑进程

改 `.py` 要重启；改 `.env` 也要重启；`--reload` 只管前者。
排查顺序永远是：**先确认跑的是不是新代码**，再怀疑代码本身。

### 4. 工具链的坑要主动绕开

- PowerShell 会吃掉 `curl.exe -d` 里的双引号 → 改用 Python 脚本发请求；
- `Invoke-RestMethod` 遇到 4xx 直接抛异常 → 看不到 422 的响应体；
- 记事本可能把文件存成 `.py.txt` → 存完用 `dir` 确认扩展名。

这些不是知识，是**方言和陷阱**。踩过一次就记下来。

## 六、如果重来一次，我会按这个顺序做

1. **先起服务、再写代码**：先让 `GET /health` 返回 200，确认骨架通；
2. **校验先只写一个字段**：跑通 `{}` → 422 再补其余；
3. **鉴权前先想清楚顺序**：`Depends` 在前、body 校验在后，这个顺序决定你看到 401 还是 422；
4. **每加一个功能，立刻配一条测试**，而且用真实调用方的格式；
5. **改完必须重启**，然后先用一条 curl/脚本确认"新代码真的在跑"，再看业务；
6. **提交前 `git status` 看一眼**，用 `git add <文件>` 点名，别 `git add .`。
